# 섀도우 전진검증 — 주간 분석 런북

사용자가 "섀도우 분석해줘" / "이번 주 섀도우 성적표 봐줘" 등을 요청하면 **이 절차 그대로** 따른다.
(관련: 연구소 Notion 페이지, `backtest/shadow_forward.py`, `.github/workflows/shadow.yml`)

## STEP 0 — 최신 원장 확보
매주 월 16:00 KST에 GitHub Actions가 `shadow_ledger.json`(저장소 루트)을 자동 커밋한다.
- `git pull` 후 루트 `shadow_ledger.json`을 읽는다. (또는 사용자가 붙여넣은 텔레그램 메시지를 그대로 사용)
- 로컬에서 직접 돌리려면: `bash scripts/run_shadow_weekly.sh` (S3 sync + 파이프라인).

## STEP 1 — 소스 먼저 확인 (가장 중요)
`source` 필드를 본다.
- `quant_signals(폴백 top_10)` → **부트스트랩**. 과거 데이터 사후 계산 = **진짜 OOS 아님**. 판단 근거로 쓰지 말 것.
- `universe` → **진짜 전진검증(OOS)**. 2026-08-03부터 누적. 이때부터 의미 있는 판단 시작.

## STEP 2 — 절대값 말고 '상대'로 읽기
하락 주는 다 마이너스가 정상. **벤치마크(KODEX200) 대비**로 해석한다.
1. 각 전략 vs **벤치(KODEX200)**: 이기면(덜 잃거나 더 벌면) 공식이 값어치를 한다.
2. 각 전략 vs **실계좌**: 어떤 종이 공식이 실제 운용보다 나은가?
3. **누적 추세**(여러 주)로 본다. 한 주 결과로 결론짓지 않는다.

## STEP 3 — 짚어줄 것
- 전략 간 상대: DD가드 baseline / 집중형 / 속도형 / 레버리지 / 콤보가드 중 무엇이 벤치·실계좌를 이기나.
- 가드 동작: 급락 주에 현금 대피가 방어했나. 콤보(SMA+DD)가 DD 단독과 갈리나(깊은 급락은 보통 동률).
- 이상 신호: 한 전략이 갑자기 크게 벌거나 잃음, 실계좌가 모든 종이 공식에 뒤짐 등.

## STEP 4 — 보고 형식 (사용자에게)
1. **소스**(부트스트랩/OOS)와 그 의미를 먼저 명시.
2. 표: 전략별 누적 vs 벤치 vs 실계좌.
3. 눈에 띄는 변화 1~2개.
4. **결론 가능 여부**: 대개 "아직 표본 부족, 경향만" — 몇 달 누적 전엔 승격 판단 금지.

## 항상 붙일 캐비앗
- 8/3 전 = 부트스트랩(급락장 1구간 편향).
- 섀도우는 지수/종이 기준 — 실제 고베타 포트폴리오와 다를 수 있음.
- in-sample/표본 얇음. 어떤 공식도 아직 매수보유를 확실히 못 이김(핵심 부가가치는 MDD 방어).
- 승격(실전 반영) 판단은 **여러 달 OOS 누적 + 실제 유니버스 재검증** 후에만.
